### 5. Experiments with AI and creative software

Before RaQuel Synths became the main creative-technology ecosystem, I also experimented with generative AI and small software ideas.

#### Rock Composer AI — discontinued prototype

[rock-composer-ai](https://github.com/anaraquel00/rock-composer-ai) is an early Python / Hugging Face / Gradio prototype for **AI-assisted lyric generation and basic chord progressions**.

It does **not generate audio or complete music**. The project was intentionally discontinued as general-purpose generative AI tools became much more capable for lyric-generation workflows.

I keep it because it documents an early attempt to connect **software + AI + music** — a direction that later became much more important in my work.

Other experimental repositories from this broader period include AI agents, prompt experiments and small automation-oriented ideas. They are part of the exploration phase rather than claims of production AI engineering.

## 🎛️ RQS Studio — Current Product Chapter

[RQS Studio](https://studio.raquelsynths.com/app) is the most technically demanding project in my current work, but it is presented here as the **latest chapter of the journey**, not as if everything before it never happened.

RQS Studio combines a browser-facing Angular application with backend audio-processing services.

Current product areas include:

- S3-backed audio upload workflows
- mastering previews and final master delivery
- Web Audio A/B comparison
- setlist creation and rendering
- stem-separation requests
- authentication and account state
- deep-link tooling for music platforms

**Frontend:** Angular 20, TypeScript, RxJS, Angular Signals, Web Audio API, Supabase  
**Backend / Processing:** Node.js, Express, Python, FFmpeg, Demucs, AWS S3

**Product:** https://studio.raquelsynths.com/app  
**Frontend repository:** https://github.com/anaraquel00/rqs-daw-frontend  
**Backend repository:** https://github.com/anaraquel00/rqs-daw-backend

RQS Studio is also where I am gaining practical collaborative-development experience across separate repositories through Pull Requests, code review, integration checks and pre-merge validation.

> The product is evolving toward a B2B SaaS direction, but I intentionally distinguish current capabilities from future requirements such as organization-level tenancy, stronger authorization, full subscription lifecycle handling and observability.

## 🤝 Engineering Practice Today

My current development practice increasingly includes:

- Git / GitHub workflows
- Pull Requests
- code review
- integration validation
- documentation based on repository evidence
- explicit separation between implemented functionality and roadmap claims
- careful handling of security and SaaS claims
- collaboration across frontend and backend codebases

One principle I try to keep consistent:

> **A feature that appears in a UI, a feature that is fully integrated, a server-enforced control and a roadmap idea are four different things.**
